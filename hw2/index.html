Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

What is de Casteljau's Algorithm:

De Casteljau's algorithm is a recursive method used to evaluate a point on a Bezier curve for a given parameter t ∈ [0, 1]. Given n control points, we perform n−1 linear interpolations between adjacent points to create a new set of n−1 intermediate points. For any two adjacent control points pi and pi+1, the intermediate point p'i is calculated as: p'i = (1 − t)pi + tpi+1 We repeat this process recursively until only a single point remains, which gives the point on the Bezier curve at parameter t.

How We Implemented de Casteljau's Algorithm:

We implemented the logic within the evaluateStep function. Using a for loop to traverse the input vector points, we perform iterative linear interpolation. For each pair of adjacent points pi and pi+1, we applied the Lerp formula using the class member variable this->t as the interpolation parameter and calculated the intermediate point using the formula above. Each newly computed point was then added to the result vector using push_back(). When key E is pressed, this function is called repeatedly and the program reduces the number of points by 1 on each step until a single point remains, which is then used by viewer to render the Bezier curve.

Part 2: Bezier surfaces with separable 1D de Casteljau

How does de Casteljau's Algorithm extends to Bezier Surface:

The de Casteljau alogrithm extends to Bezier surfaces by applying the same 1D interpolation algorithm across 2 dimensions. A Bezier patch is an n x n grid of control points and 2 parameters, u and v. To evaluate a point on the surface, we first treat each row of n control points as independent Bezier curves and evaluate it at parameter u. This will reduce the grid to a single column of n new points. This resulting column is then treated as a final Bezier curve and evaluated at parameter v. The final point produced will lie on the Bezier surface at (u, v).

How We Implemented de Casteljau's Algorithm for Bezier Surface:

Using a 3D version of the recursive step from part 1, evaluateStep computes n - 1 intermediate points using linear interpolation, given a vector of 3D points and parameter t. evaluate1D then takes an initial vector of points and repeatedly calls evaluateStep in a while loop until only 1 point remains, then returns the point. evaluate then handles the 2D grid. It iterates through each row of the control points and call evaluate1D on each parameter u. Then it calls evaluate1D at parameter v to produce the final surface point.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

How We Implemented Area-Weighted Vertex Normals:

To compute, we have to iterate through all the faces adjacent to a vertex by traversing the half-edge data structure. Starting from the vertex's half edge, we use h_twin->next() to visit each neighbouring triangle. For each non-boundary face, we computed the face normal using the cross product of two edge vectors from the vertex. The magnitude of the cross product is twice the area of the triangle, hence the resulting vector is naturally weighted by the face's area. Accumulating all the weighted vectors for all adjacent faces and normalising the result will give the unit normal at the vertex.

Part 4: Edge flip

How We Implemented Edge Split Operation:

The edge flip is implemented as a local topological transformation that rotates a shared edge within a pair of adjacent triangles, without add or removing geometry. Firstly, we ensure that the operation does not flip any boundary edge by checking the isBoundary() status of the edge's two primary half-edges. Then, to avoid errors in rewiring the pointers, we label and collect every mesh element in the 2-triangle neighbourhood. This includes the 6 internal half-edges, the 4 vertices (a, b, c, d), the 5 edges, and the 2 faces. We replace the original diagonal (b, c) with the new diagonal (a, d). The core of the implementation involves using the setNeighbours method to update the next, twin, vertex, edge, and face pointers for each of the internal half-edges in a single pass. Finally, we refresh the halfedge() handles for all affected vertices, edges, and faces to ensure every iterator in the mesh remains consistent.

Part 5: Edge split

How We Implemented Edge Split Operation:

The edge split operation works by inserting a new vertex m at the midpoint of a shared edge (b, c) between 2 triangles (a, b, c) and (c, b, d), which subdivides them into 4 smaller triangles (b, m, a), (m, c, a), (m, b, d) and (c, m, d). First we check that the operation does not split any boundary edges by checking isBoundary(), like in task 4. We start by retrieving the existing 6 halfedges, 4 vertices, 2 faces and 4 edges of the orignial 2 triangles. Then we create new elements: vertex m at the midpoint, 3 new edges (m-a, m-d, m-c), 2 new faces, and 6 new halfedges. The original edge e0 is reused as the b-m edge, while a new edge e7 is created for the m-c part, which splits the original edge into 2 essentially. After creating new elements, we reassign their neighbors using setNeighbors() to create the 4 resulting triangles.

Part 6: Loop subdivision for mesh upsampling

How We Implemented Loop Subdivision for Mesh Upsampling:

First, new positions for all old and new vertices are pre-computed from the original mesh before any topology changes. The old vertices use the weighted average (1 - n·u) · pos + u · neighbor_sum, and new edge midpoint vertices use 3/8 · (A + B) + 1/8 · (C + D). All original edges and vertices are flagged isNew = false at this stage.

Second, all original edges are collected into a vector before splitting begins to avoid iterating over newly created edges. Each edge is split, the returned vertex is flagged isNew = true and assigned its pre-computed position. Then, any new edge connecting one old and one new vertex is flipped.

Finally, all vertex positions are updated from their newPosition values.

The sharp corners and edges are progressively rounded with each subdivision iteration, since Loop subdivision is an prooximating scheme. The vertices are pulled toward their neighbors rather than staying fixed. Pre-splitting an edge near a sharp feature before subdividing can help maintain its sharpness, as the higher local vertex density constrains how far the averaging can pull the corner inward.

The cube.dae subdivides asymmetrically because its faces are triangulated with diagonals, giving vertices unequal degrees and therefore unequal Loop subdivision weights. Pre-processing by splitting each face into an X pattern makes all vertices degrees equal, so the cube subdivides symmetrically into a smooth shape.

Interesting Implementation / Debugging Tricks:

One main issue we encountered was inconcsistent spikes appearing after the first subdivision. This was caused by the m–c edge (upper half of the original split edge) being incorrectly marked isNew = true, causing it to be flipped when it shouldn't be. Marking both halves of the original split edge as isNew = false and only the two new diagonal edges as isNew = true resolved the issue.
