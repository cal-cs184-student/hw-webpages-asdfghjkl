Part 1: Ray Generation and Scene Intersection

How We Implemented Ray Generation and Primitive Intersection Pipeline

The rendering pipeline for ray generation and primitive intersection consists of several key stages

1. Pixel Sampling Stage:

For each pixel in the image:

  • Input: Pixel coordinates (x, y) in image space, where (0,0) is at the bottom-left corner
  • Anti-aliasing: Generate ns_aa sample points within the pixel using a uniform grid sampler
  • Coordinate transformation: Convert pixel coordinates to normalized coordinates [0,1] × [0,1]
  • Sample accumulation: Average the radiance values from all samples to produce the final pixel color

Each sample point is obtained via gridSampler->get_sample(), which provides a uniform random offset in [0,1) × [0,1) added to the pixel origin before normalization.

2. Camera Ray Generation Stage (Camera::generate_ray)

For each sample point:

  • Input: Normalized image coordinates (x, y) ∈ [0,1] × [0,1]
  • Camera space transformation: Map to the virtual sensor plane at z = -1, with bottom-left at (-tan(hFov/2), -tan(vFov/2), -1) and top-right at (tan(hFov/2), tan(vFov/2), -1)
  • Ray direction: Computed from the camera origin (0,0,0) through the sensor point
  • World space transformation: Direction transformed via the c2w rotation matrix; origin set to pos
  • Output: A normalized world-space ray with min_t = nClip, max_t = fClip

3. Primitive Intersection Stage

Once rays are generated, each ray is tested against scene geometry:

  • BVH traversal: Quickly culls geometry that cannot be hit (Part 2)
  • Primitive intersection test: Runs Möller–Trumbore (triangles) or quadratic solving (spheres) on candidate primitives
  • Closest-hit selection: Only the intersection with the smallest valid t ∈ [tmin, tmax] is kept, updating max_t so farther intersections are discarded

Triangle Intersection Algorithm (Möller–Trumbore)

Given a triangle with vertices p₁, p₂, p₃ and a ray R(t) = O + tD:

  1. Compute edge vectors e₁ = p₂ − p₁, e₂ = p₃ − p₁
  2. Compute h = D × e₂, determinant a = e₁ · h; if |a| < ε, ray is parallel — no intersection
  3. Compute s = O − p₁, barycentric coordinate u = (s · h) / a; if u ∉ [0,1], miss
  4. Compute q = s × e₁, barycentric coordinate v = (D · q) / a; if v < 0 or u + v > 1, miss
  5. Compute t = (e₂ · q) / a; if t ∉ [tmin, tmax], miss

On a valid hit, the surface normal is interpolated using barycentric coordinates w = 1 − u − v:

n = w·n₁ + u·n₂ + v·n₃

This method is efficient because it avoids computing the plane equation explicitly, solving directly for t, u, v in one linear system.

Sphere Intersection

Given a sphere with center C and radius r, substituting R(t) = O + tD into |R(t) − C|² = r² yields the quadratic:

at² + bt + c = 0

where:

  • a = D · D
  • b = 2D · (O − C)
  • c = |O − C|² − r²

If the discriminant Δ = b² − 4ac < 0, no intersection exists. Otherwise, both roots:

t₁, t₂ = (-b ± √Δ) / (2a)

are computed and the smaller valid t ∈ [tmin, tmax] is selected.

The surface normal is computed analytically as:

n = (R(t) − C) / r

The implementation splits this across three functions: test(), has_intersection(), and intersect().
